## 2. 内容结构：按原稿“四越四墙”区分成效与边界（claude-v125）

原稿第三部分以“四越”写成效（P073—P096），以“四墙”写组织边界（P098—P124），P125 总括“四道墙弹回的实为同一事物——边界”。大屏此前的四个组织问题（审批权限 / 法定程序 / 数据责任 / 平台衔接）与原稿结构不一一对应，且各页成效与问题混排。本轮改为：

| 专题 | 成效（之越，原稿标题） | 边界（回弹，原稿标题） | 边界依据 |
|---|---|---|---|
| 事项集成 | 部门事项转场景，一次提交联审批 | 前台合，后台分，职权难打破 | P103 受理权可以集中，审批权则不能；P104 字段统一、系统仍分 |
| 流程协同 | 前台集成一次办，后台并联协同转 | 前台并，后台串，程序难再造 | P106 法定受理条件、审查标准、签批层级；P107 个案协调与人工兜底；P109 |
| 数据流通 | 证照调用免材料，数据流通提效率 | 权属锁，安全悬，决策难跨越 | P111 专网隔离；P113 逐项谈签、责任无说法；P114 人工签字兜底 |
| 监管统筹 | 只查一次减干扰，协同监管向纵深 | 条块分，跨层隔，协同难贯通 | P121 系统林立、标准各异；P122—P124 市区受理平台未对接 |

- **每页副标题**写明“X之越 · X回弹”；**面板标题**统一加“成效 /”“边界 /”前缀；**本页要点**统一为“成效：……；边界：……”。
- **总览**：右上“四道墙”改为原稿四个回弹，各配一句原稿依据；四张专题卡第一行为成效（青）、第二行为边界（金）；右下改为 P108—P109“前台减负，后台增负”与 P125 总括。
- **事项与流程的区分**：事项集成只讲“审批权在哪里”（P103/P104：受理集中、审批权与系统仍分属）；流程协同只讲“程序怎么走”（P106：三列改为法定受理条件 / 审查标准 / 签批层级，去掉原先与事项页重复的 P103“原业务系统”列）。
- **数据流通**：四个并列研究问题（授权 / 核验 / 适用 / 异常）不是原稿表述，改为原稿数据回弹的四处表现：专网隔离、逐项协商、责任悬空、人工兜底，各自链接对应段落。
- **监管统筹**：右下由“区域协作进展”改为原稿监管回弹三节点（P121 / P122 / P123）；跨区联合检查进展保留为“成效延伸”一行；保留 V123 的口径——P122—P124 所指为综窗受理平台，与检查业务分别阅读。
- **组织条件台账**（`v7/data.js` constraints）：四项标签改为四个回弹，与四个专题一一对应，段落只保留各自小节（移除属于“限度之存 / 未尽之问”的 P134、P139）。
- **矛盾现场**（`v14/case-story.js` stories / core）：交叉对应改为一一对应；流程协同移除 P103（事项小节）与 P095（信用修复，属监管之越）；监管统筹加入 P121；核心问题说明改为原稿 P098 / P125 的表述。
